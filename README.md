# Безопасный ALIAS

Статическая PWA-игра по охране труда и промышленной безопасности. Игра работает на одном устройстве, восстанавливает активный раунд после перезагрузки и доступна офлайн после первого успешного открытия.

## Требования

- Node.js 20 или новее;
- Chrome/Chromium для браузерных тестов;
- HTTPS на production-хостинге.

## Локальный запуск

Для быстрого запуска в Windows дважды щёлкните `start.bat`. Сервер откроется в отдельном свёрнутом окне, а приложение — в браузере. Чтобы остановить сервер, закройте окно `Safety ALIAS Server`.

Ручной запуск:

```powershell
python -m http.server 8000
```

Откройте `http://localhost:8000`. Запуск через `file://` не поддерживает service worker и не является полноценной проверкой PWA.

## Проверки и сборка

```powershell
npm test
npm run build
```

Тесты проверяют JavaScript, manifest, размеры иконок, структуру карточек, абсолютный таймер, паузу, восстановление состояния, защиту счёта и offline-навигацию. Production-артефакт создаётся в `dist/`.

## Публикация

Workflow `.github/workflows/pages.yml` запускает тесты, собирает `dist/` и публикует его через GitHub Pages. После добавления GitHub remote:

1. отправьте ветку `main` в репозиторий;
2. в Settings → Pages выберите Source: **GitHub Actions**;
3. защитите environment `github-pages` и разрешите deployment только из `main`;
4. настройте домен и HTTPS в параметрах репозитория.

Файл `_headers` содержит CSP, HSTS и остальные production-заголовки для Netlify/Cloudflare Pages или совместимого reverse proxy. GitHub Pages не применяет этот файл как конфигурацию; для него базовая CSP дополнительно задана через `<meta>`, но заголовки необходимо контролировать на CDN/reverse proxy.

## Структура

- `index.html` — разметка экранов;
- `styles.css` — интерфейс и адаптивность;
- `cards.csv` — утверждённый исходный набор карточек;
- `content.js` — сгенерированные категории и карточки;
- `event-engine.js` — конфигурация и расчёт игровых событий;
- `app.js` — состояние и игровая логика;
- `sw.js` — offline-кэш и обновления;
- `CONTENT_REVIEW.md` — обязательный протокол экспертизы контента;
- `tests/` — статические и браузерные проверки.

## Содержание

Набор из 600 карточек утверждён владельцем проекта. Версия и контрольная сумма зафиксированы в `CONTENT_REVIEW.md`. После изменения `cards.csv` пересоберите модуль и выполните проверки:

```powershell
npm run content:import
npm run lint
npm test
npm run build
```

## Ограничения

Backend, учётные записи, синхронизация устройств и централизованный редактор карточек отсутствуют. Они нужны только при соответствующих продуктовых требованиях. Не добавляйте конфиденциальные или персональные данные в публичный репозиторий.
